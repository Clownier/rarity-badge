# 稀有度徽章 (Rarity Badge) 游戏设计文档

## 1. 游戏概述

《稀有度徽章》是一款基于概率和数值膨胀的放置类游戏。玩家通过不断"掷出"来获取不同稀有度的徽章，收集微光资源和成就点，升级各项属性，追求更加稀有的徽章。游戏设计简洁而富有成就感，通过概率和数值的不断提升来激励玩家持续游玩。游戏支持中英文双语切换，并提供排行榜系统。

## 2. 核心玩法

### 2.1 基础机制

- **掷出机制**：玩家点击"掷出"按钮（或自动掷出版本中自动触发）进行一次随机掷出
- **冷却时间**：每次掷出后有冷却时间，初始为3秒
- **稀有度系统**：掷出结果有不同稀有度的徽章，从"普通"到极其稀有的结果
- **资源获取**：每次掷出根据获得的稀有度获得相应数量的"微光"资源
- **升级系统**：使用微光资源升级属性，提高获取稀有结果的概率和效率
- **重生系统**：达到超级史诗(id≥8)后可重生，进行"重生掷出"（概率性7级稀有度），获得成就点(AP)
- **成就系统**：首次发现稀有度/达成里程碑时解锁成就（纯展示，不产出货币）
- **重生升级**：使用 AP 购买 4 项永久继承属性（幸运/微光/重置运/AP倍率）

### 2.2 游戏循环

1. 玩家进行掷出操作
2. 获得随机稀有度徽章和相应微光资源
3. 使用微光资源购买当前周期的升级，提高掷出效率和稀有度概率
4. 达到超级史诗后可选重生，进行重生掷出获得 AP
5. 使用 AP 购买重生升级，提升下个周期的起点
6. 重复以上步骤，追求更高的稀有度
7. 查看统计，追踪进度

## 3. 界面设计

### 3.1 主界面

主界面分为五个主要标签页：主界面、索引、成就、统计和选项。

#### 3.1.1 顶部区域
- 游戏标题："稀有度徽章"/"Rarity Badge"（根据语言设置）
- 资源显示：
  - 当前拥有的微光数量
  - 当前拥有的成就点数量

#### 3.1.2 掷出结果区域
- 显示最近一次掷出的徽章图案、名称和稀有度

#### 3.1.3 标签页导航
- 主界面：游戏主要交互区域
- 索引：查看已发现的稀有度记录
- 成就：查看已解锁和未解锁的成就
- 统计：查看详细游戏数据和图表
- 选项：游戏设置和存档管理

#### 3.1.4 主界面内容
- **掷出按钮**：
  - 显示"掷出"/"Roll"文字（根据语言设置）
  - 显示当前冷却状态（倒计时或"就绪"/"Ready"）
  - 冷却中为灰色，就绪后为亮色
  - 自动掷出版本中，冷却结束后自动触发

- **当前周期升级区域**：显示三种可升级属性
  - **幸运**/**Luck**：提高获得稀有结果的概率
    - 显示当前值和升级后的值
    - 显示升级所需微光数量
  - **间隔**/**Interval**：减少掷出的冷却时间
    - 显示当前值和升级后的值
    - 显示升级所需微光数量
  - **微光**/**Shimmer**：增加每次掷出获得的微光倍率
    - 显示当前值和升级后的值
    - 显示升级所需微光数量

- **重生区域**（条件满足时显示）：
  - 当前 AP 数量
  - **重生按钮**：条件为最佳掷出 ≥ 超级史诗(id:8)
    - 显示重生后可继承的 luck 倍率 (1.3^(id-7) × regenRLuck)
    - 点击后触发重生：重生掷出 → 结算 AP → 重置周期
  - 4 项重生升级（使用 AP 购买）：
    - **幸运**：regenLuck ×= 2（继承幸运）
    - **微光**：regenShimmerMulti ×= 1.5（继承微光倍率）
    - **重置运**：regenRLuck ×= 2.5（重生掷出更易出高稀有度）
    - **AP 倍率**：regenGlistenMulti ×= 1.5（重生获得更多 AP）

- **最近掷出记录**：
  - 标题："最近10次投掷"/"Last 10 Rolls"
  - 列表显示最近10次掷出的徽章图案、稀有度和概率

- **最佳掷出**：
  - 显示迄今为止获得的最佳（最稀有）掷出徽章

- **重生按钮**（条件满足时显示）：
  - 当最佳掷出达到"史诗"或更高稀有度时显示
  - 显示重生后可获得的成就点数量
  - 点击后触发重生机制

### 4.2 成就系统

成就分为以下几类（成就为纯展示，不产出货币）：

#### 4.2.1 徽章收集成就
- 首次发现每种稀有度的徽章（id:7+）
- 无奖励（仅成就展示）

#### 4.2.2 徽章数量成就
- 收集特定数量的同一稀有度徽章
- 阶段：1000次、10000次（无奖励）

#### 4.2.3 总体游戏进度成就
- 总掷出次数里程碑：100次、1000次、10000次、100000次
- 重生次数里程碑：1次、5次、10次、50次、100次

### 4.3 数值膨胀计算

#### 4.3.1 掷出概率计算

掷出时，游戏生成一个0到1之间的随机数，然后除以玩家的幸运值：
```
x = Math.random() / player.luck
```
原版额外除 regenLuck: `x = Math.random() / player.luck / player.regenLuck`

然后从最稀有到最常见遍历稀有度表，第一个概率大于等于x的稀有度即为结果。等价于 `Math.random() ≤ rarity.chance × luck`。

#### 4.3.2 微光获取计算

每次掷出获得的微光数量：
```
获得微光 = rarityId × player.shimmerMulti
```
线性公式（原版 Rarity Toy），稀有度 id 从 1(Common) 到 28。

#### 4.3.3 当前周期升级价格递增

- **幸运升级**：
  - 初始价格：10微光
  - 每次升级后价格变为原价的3倍
  - 每次升级效果：幸运值乘以2.5

- **间隔升级**：
  - 初始价格：10微光
  - 每次升级后价格变为原价的2.25倍
  - 每次升级效果：间隔时间乘以0.85（减少15%）

- **微光升级**：
  - 初始价格：25微光
  - 每次升级后价格变为原价的4倍
  - 每次升级效果：微光倍率乘以2

#### 4.3.4 重生升级（原全局升级替代）

使用 AP（成就点）购买，跨重生保留，乘法叠加：

| 升级 | 初始价 | 价格增长 | 效果 |
|------|--------|---------|------|
| 幸运(regenLuck) | 2 AP | ×4 | regenLuck ×= 2，luck ×= 2 |
| 微光(regenShimmerMulti) | 2 AP | ×5 | regenShimmerMulti ×= 1.5，shimmerMulti ×= 1.5 |
| 重置运(regenRLuck) | 5 AP | ×4 | regenRLuck ×= 2.5 |
| AP倍率(regenGlistenMulti) | 8 AP | ×4 | regenGlistenMulti ×= 1.5 |

#### 4.3.5 重生机制

条件：最佳掷出 ≥ 超级史诗 (id:8)

重生掷出：
```
x = Math.random() / player.regenRLuck / (1.3 ^ (player.bestRoll.id - 7))
遍历 REGENRARITIES[] 7级稀有度，首次 x ≤ chance 的中选
AP获取 = selectedRegenRarityId × player.regenGlistenMulti
```

7级重生稀有度：Expected(1/1), Abnormal(1/10), Anomalous(1/65), Divergent(1/875), Distorted(1/5150), Aberrant(1/264785), Paradoxical(1/777777777)

重置内容：
- luck → regenLuck（继承）
- shimmerMulti → regenShimmerMulti（继承）
- shimmer → 0
- 当前周期升级重置初始价格
- 投掷间隔 → 3s
- 掷出记录和最佳掷出清空

### 4.4 离线进度系统

当玩家离线时，游戏会记录离线开始时间，并在玩家返回时计算离线期间的进度：

- 离线掷出次数 = 离线时间（秒）/ 当前掷出间隔
- 离线获得微光 = 离线掷出次数 × 平均微光收益 × 离线效率系数（默认为0.8）
- 离线获得的新徽章和成就会在玩家返回时计算

离线收益摘要会在玩家返回游戏时显示，包括：
- 离线时长
- 获得的微光数量
- 新发现的徽章（如果有）
- 达成的成就（如果有）

## 5. 存档系统

### 5.1 自动存档
- 游戏状态会自动保存到浏览器的localStorage中
- 自动保存频率可在选项中设置

### 5.2 手动存档
- 玩家可以在选项界面手动保存游戏
- 可以导出存档为加密的Base64字符串
  - 使用简单的加密算法（如XOR加密或AES加密）处理存档数据
  - 确保导出的字符串不易被直接修改
- 可以导入之前导出的加密存档字符串
  - 导入时进行解密处理
  - 导入存档时会显示警告：导入的存档不计入排行榜

### 5.3 初始化功能
- 选项界面提供"初始化"按钮
- 点击后显示确认对话框："确定要格式化本机全部游戏数据吗？此操作不可撤销。"
- 确认后清除所有localStorage中的游戏数据，包括：
  - 当前游戏存档
  - 排行榜参与状态
  - 游戏设置
  - 其他相关数据

### 5.4 存档数据结构
存档包含玩家的完整状态，包括：
- 总掷出次数
- 各稀有度的发现记录
- 当前微光数量
- 成就点数量
- 各项当前周期升级的等级和价格
- 各项全局升级的等级
- 最近的掷出记录
- 最佳掷出记录
- 重生相关数据
- 成就完成状态
- 游戏设置（语言等）
- 排行榜参与状态（不包含玩家昵称）
- 离线时间记录

## 6. 排行榜系统

### 6.1 排行榜机制

- 排行榜基于以下指标排名：
  - 主要指标：获得的总成就点数量
  - 次要指标：最高稀有度徽章
  - 辅助指标：总掷出次数

- 排行榜显示前100名玩家

### 6.2 排行榜规则

- 只有未导入存档的游戏才能参与排行榜
- 玩家可以选择是否参与排行榜
- 参与排行榜需要在首次刷新排行榜时输入玩家昵称
- 玩家昵称不保存在本地存档中，仅与服务器关联

### 6.3 排行榜交互

- **刷新排行榜**：
  - 点击"刷新排行榜"按钮与服务器同步数据
  - 首次点击时弹出昵称输入框
  - 同步成功后显示最新排行榜数据

- **退出排行榜**：
  - 点击"退出排行榜"按钮可以选择不再参与排行榜
  - 退出后数据不再上传，但已上传的数据仍保留在服务器

### 6.4 排行榜显示

- 每个玩家条目包含：
  - 排名
  - 玩家昵称
  - 成就点数量
  - 最高稀有度徽章
  - 总掷出次数

## 7. 双语支持

### 7.1 语言切换机制

- 游戏支持中文和英文两种语言
- 语言设置保存在游戏存档中
- 切换语言时即时生效，无需重启游戏

### 7.2 翻译内容

所有游戏文本都提供中英文两种版本，包括：
- 界面文本
- 徽章名称和描述
- 成就名称和描述
- 提示和教程文本
- 错误和警告信息

### 7.3 语言资源管理

- 使用键值对形式存储所有文本
- 根据当前语言设置动态加载对应文本
- 支持未来扩展更多语言

## 8. 技术实现指南

### 8.1 推荐技术栈

- **前端框架**：React + TypeScript
- **状态管理**：React Hooks 或 Redux
- **样式**：CSS/SCSS 或 Tailwind CSS
- **图表库**：Chart.js 或 Recharts
- **国际化**：i18next
- **加密**：CryptoJS
- **构建工具**：Vite
- **部署**：静态网站托管（如Netlify、Vercel等）
- **排行榜后端**：Firebase Realtime Database 或 简单的REST API
